# 职业规划 Agent 实施任务与验收标准

工程执行顺序以《职业规划Agent详细实施计划.md》为准；本文件保留阶段任务和验收清单。

## 1. 实施原则

- 每个阶段都必须产生可运行、可验证的结果。
- 先打通一条最小链路，再扩展工具数量。
- 不在一期同时重写首页、爬虫、支付和所有旧 AI 功能。
- 新 Agent 与旧 AI 功能并行一段时间，确认稳定后再下线旧入口。
- 业务逻辑优先放在确定性服务，Agent 只做编排和自然语言交互。

## 2. Phase 0：需求和基线

### 任务

- [ ] 冻结首页保留功能和下线功能。
- [ ] 确认 `/agent` MVP 用户流程。
- [ ] 整理现有 AI endpoint 到 Agent 工具的映射。
- [ ] 确定 SSE 事件格式。
- [ ] 确定 AgentRun 的状态机。
- [ ] 修复或隔离当前测试中的旧路由和旧数据库依赖。
- [ ] 建立 Agent 评估样例集，至少覆盖 10 个真实问题。

### 交付物

- 产品范围确认。
- 接口草案。
- 数据模型草案。
- 风险清单。
- 评估样例集。

### 验收

- 产品、前端和后端对一期范围使用同一份文档。
- 不再新增独立职业分析 AI 页面。

## 3. Phase 1：数据模型和 API 骨架

### 任务

- [ ] 新增 `agent_conversations` 表。
- [ ] 新增 `agent_messages` 表。
- [ ] 新增 `agent_runs` 表。
- [ ] 新增 `career_profiles` 表。
- [ ] 编写 Alembic migration。
- [ ] 实现会话 CRUD。
- [ ] 实现消息写入和历史查询。
- [ ] 实现运行创建、状态查询和取消。
- [ ] 加入用户资源权限校验。

### 验收

- 用户只能访问自己的会话、消息和运行。
- 数据库迁移可以在已有数据库上升级。
- 重复请求不会创建无法追踪的孤儿运行。
- API 错误统一使用当前项目响应格式。

## 4. Phase 2：工具层

### 任务

- [ ] 建立工具基类和注册表。
- [ ] 为每个工具定义输入和输出 Pydantic Schema。
- [ ] 封装 `search_jobs`。
- [ ] 封装 `get_market_overview`。
- [ ] 封装 `get_skill_demand`。
- [ ] 封装 `compare_cities`。
- [ ] 封装 `compare_industries`。
- [ ] 封装 `get_major_directions`。
- [ ] 为 ES 失败和 PostgreSQL 降级统一返回格式。
- [ ] 为工具增加超时、重试和日志。

### 验收

- 工具不能直接执行模型生成的 SQL 或原始 DSL。
- 工具结果包含样本量、筛选条件、数据时间和来源。
- ES 不可用时，工具不会返回不符合契约的结构。
- 工具异常不会泄露内部错误细节。

## 5. Phase 3：Agent Runtime

### 任务

- [ ] 实现消息理解节点。
- [ ] 实现用户信息提取节点。
- [ ] 实现信息完整性判断。
- [ ] 实现分析计划节点。
- [ ] 实现工具选择和调用节点。
- [ ] 实现证据充分性判断。
- [ ] 实现最终回答节点。
- [ ] 实现运行次数、工具次数和执行时长限制。
- [ ] 实现运行失败、取消和超时状态。
- [ ] 保存结构化运行快照。

### 验收

- Agent 不会在信息不足时凭空补全关键事实。
- Agent 能主动提出澄清问题。
- Agent 至少调用一个真实市场工具后再输出市场结论。
- Agent 最多执行规定次数，不会无限循环。
- 模型调用失败时运行状态为 `failed`，不能伪装成成功空结果。

## 6. Phase 4：SSE 实时事件

### 任务

- [ ] 实现 `GET /agent/runs/{run_id}/events`。
- [ ] 定义事件 ID 和顺序号。
- [ ] 支持客户端断线后从最后事件继续读取或查询最终状态。
- [ ] 输出计划、工具调用、工具结果摘要和回答增量。
- [ ] 防止同一运行重复消费导致重复执行。
- [ ] 增加运行取消事件。

### 验收

- 首个运行事件在 2 秒内返回，环境依赖除外。
- SSE 断开重连不会启动第二个 AgentRun。
- 运行结束后一定收到 `run_completed` 或 `run_failed`。
- 前端不会因为单个坏事件导致整个会话崩溃。

## 7. Phase 5：前端 Agent 工作台

### 任务

- [ ] 新增 Agent 路由和页面。
- [ ] 新增 Agent Pinia store。
- [ ] 实现自然语言输入框。
- [ ] 实现消息列表。
- [ ] 实现工具执行状态展示。
- [ ] 实现 SSE 连接和重连。
- [ ] 实现运行取消。
- [ ] 实现会话历史。
- [ ] 实现右侧职业画像和行动建议卡片。
- [ ] 增加移动端布局。

### 验收

- 用户不需要先选择“专业分析”或“职业罗盘”等功能。
- 页面能区分回答、工具状态、追问和错误。
- 页面刷新后可以恢复会话和运行状态。
- 未登录用户不能访问需要个人画像的 Agent 能力。

## 8. Phase 6：画像和计划闭环

### 任务

- [ ] 记录用户明确确认的职业画像。
- [ ] 支持用户修改画像字段。
- [ ] 新增职业目标和约束。
- [ ] 新增行动计划和计划项。
- [ ] 允许 Agent 读取画像和计划。
- [ ] 根据用户反馈更新方向排序。
- [ ] 后续接入简历解析结果。

### 验收

- Agent 能记住用户在历史会话中确认的信息。
- 未确认的信息不会覆盖用户已确认信息。
- 用户可以查看、修改和删除画像。
- 行动计划有明确状态，不以生成文本代替进度数据。

## 9. 测试要求

### 后端

- [ ] 会话资源权限测试。
- [ ] AgentRun 状态转换测试。
- [ ] 工具参数校验测试。
- [ ] ES 成功和 PostgreSQL 降级测试。
- [ ] Agent 信息不足追问测试。
- [ ] Agent 工具调用上限测试。
- [ ] 模型异常和熔断测试。
- [ ] SSE 顺序和重连测试。
- [ ] 取消、超时和重复请求测试。

### 前端

- [ ] 消息流式追加测试。
- [ ] 工具状态渲染测试。
- [ ] SSE 断线重连测试。
- [ ] 页面刷新恢复测试。
- [ ] 移动端核心布局验证。

### 评估集

至少准备以下类别：

- 信息完整的职业方向问题。
- 信息不足需要追问的问题。
- 城市比较问题。
- 行业比较问题。
- 转行问题。
- 不应回答或缺少数据的问题。
- 工具不可用时的降级问题。

## 10. 发布门槛

一期上线前必须满足：

- 前后端构建成功。
- Agent migration 已在测试数据库验证。
- Agent API 权限测试通过。
- 工具契约测试通过。
- AgentRun 不存在明显重复执行问题。
- SSE 断线和取消测试通过。
- 10 个评估问题均能产生可解释结果。
- 敏感配置、上传文件和运行日志不进入版本控制。
- 旧 AI 入口仍可回退，或已完成明确下线公告。

## 11. 推荐提交拆分

建议按以下提交边界实施：

```text
1. agent: add conversation and run models
2. agent: add conversation APIs and permission checks
3. agent: add read-only market tools
4. agent: add runtime state machine
5. agent: add SSE event stream
6. frontend: add agent workspace
7. agent: add evaluation and integration tests
8. cleanup: deprecate legacy AI entrypoints
```

每个提交都应保持项目可启动，避免一次性提交完整重构导致无法定位问题。

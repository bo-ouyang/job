# Batch 8：灰度发布和旧功能共存

## 目标

在不影响现有用户的前提下发布 Agent，观察真实运行质量后再决定旧 AI 入口的迁移和下线。

## 依赖

- Batch 7 的测试、监控和 Nginx 验证全部通过。
- Agent API、SSE 和前端工作台已在 staging 完成烟囱测试。

## 功能开关

后端：

```text
AGENT_ENABLED
```

前端：

```text
VITE_AGENT_ENABLED
```

如果需要不重新构建前端调整灰度，增加运行时 capability 接口。

## 共存功能

灰度阶段继续保留：

```text
/major-analysis
/career-compass
旧 AI advice
简历解析
AiTaskPanel
aiTask.js
WebSocket 消息通知
```

Agent 不直接替换旧接口，旧接口仍由原 Controller 和 store 处理。

## 灰度步骤

1. 关闭 Agent，验证旧系统基线。
2. 对内部账号开启 Agent。
3. 验证会话隔离、工具数据、SSE 重连和取消。
4. 扩大到小比例用户。
5. 收集评估集结果、失败日志和用户反馈。
6. 验证回退开关可以立即隐藏入口并拒绝新运行。
7. 稳定后再扩大用户范围。

## 烟囱测试

```text
登录
-> 进入 /agent
-> 创建会话
-> 输入自然语言
-> 观察 run_started
-> 观察工具事件
-> 观察回答增量
-> 完成运行
-> 中断网络并刷新
-> 恢复同一 run
-> 取消另一个 run
-> 验证用户资源隔离
-> 验证旧 AI 功能
```

## 观测指标

分别记录 Agent 和 legacy AI：

- 首事件延迟。
- 总运行时长。
- 完成、失败、取消比例。
- 工具失败和数据降级比例。
- SSE 重连次数。
- 重复运行数量。
- 用户继续追问比例。
- 评估问题可解释结果比例。

## 回滚规则

出现以下任一情况立即关闭 Agent 灰度：

- 发现跨用户数据读取。
- 发现重复创建运行。
- SSE 重连触发重复执行。
- 模型错误被标记为成功。
- 工具结果缺少来源或样本量。
- Nginx 缓冲导致用户长时间无事件。
- Agent 明显影响旧 AI、首页或 WebSocket。

关闭后：

- 不再展示 Agent 导航。
- 后端拒绝新运行。
- 已运行任务继续进入安全终态或被取消。
- 保留历史会话只读。

## 旧功能下线门槛

只有满足以下条件，才允许规划旧入口下线：

- Agent 已覆盖旧功能的核心场景。
- 新旧结果经过业务对比。
- 用户历史数据迁移策略明确。
- 旧 API 已无活跃客户端依赖。
- 完成至少一个版本周期的灰度运行。
- 已有明确的回滚版本和数据库兼容方案。

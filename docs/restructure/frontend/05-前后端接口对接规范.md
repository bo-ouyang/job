# 职途AI 前后端接口对接规范

## 1. 文档目的

本文定义首页职业数据总览和职业规划 Agent 的前后端接口契约。

前端当前使用本地 Mock 数据，但 Mock 数据结构必须与本文保持一致。后端完成接口后，前端只切换数据源，不重新修改页面组件结构。

## 2. 基础约定

### 2.1 服务前缀

```text
/api/v1
```

示例：

```text
GET /api/v1/career-dashboard
POST /api/v1/agent/conversations
```

### 2.2 鉴权

需要用户画像、Agent、报告和任务数据的接口必须携带：

```http
Authorization: Bearer <access_token>
```

首页公共市场数据允许匿名访问，但返回个性化字段时必须根据登录状态和画像完整度决定是否返回。

### 2.3 ID

后端内部可以使用 Snowflake `BigInteger`，接口响应中的 ID 统一序列化为字符串：

```json
{
  "id": "184467440737095516"
}
```

前端不得将业务 ID 当作 JavaScript number 保存。

### 2.4 成功响应

继续遵循当前项目的统一响应包装：

```json
{
  "code": 200,
  "msg": "success",
  "data": {}
}
```

Axios 层会自动解包 `data`。SSE 不使用该 JSON 包装。

### 2.5 时间和金额

- 时间统一 ISO 8601，带时区：`2026-07-21T08:30:00+08:00`。
- 统计时间使用 `data_as_of`。
- 年薪单位为人民币“万元/年”，字段名必须包含 `annual_salary_wan`。
- 日薪单位为人民币“元/天”，字段名必须包含 `daily_salary_yuan`。
- 百分比使用 `0-100` 数值，不使用 `0-1` 小数。

## 3. 通用数据来源元信息

所有市场分析结果都应携带：

```json
{
  "source": "elasticsearch",
  "is_mock": false,
  "sample_size": 23842,
  "data_as_of": "2026-07-20T00:00:00+08:00",
  "filters": {
    "city_code": null,
    "major": null,
    "career": null,
    "time_range": "5y"
  },
  "warnings": []
}
```

`source` 可选值：

```text
elasticsearch
postgresql
mixed
mock
```

`warnings` 用于说明降级、样本不足、部分字段不可用等情况，不能把这些问题静默转换为空数组。

```json
    "source": "home_cta",
    "dashboard_filters": {}

```

响应：

```json
  "title": "数据分析职业规划",
```

### 6.2 会话列表和详情

```text
GET /api/v1/agent/conversations
GET /api/v1/agent/conversations/{conversation_id}
```

### 6.3 发送消息

```http
POST /api/v1/agent/conversations/{conversation_id}/messages
Idempotency-Key: <client-generated-uuid>
```

请求：

```json
{
  "content": "我在产品经理和数据分析之间犹豫，应该如何选择？",
  "context": {
    "source": "suggested_question",
    "dashboard_section": null,
    "filters": {}
  }
}
```

响应：

```json
{
  "message": {
    "id": "message-id",
    "role": "user",
    "content": "我在产品经理和数据分析之间犹豫，应该如何选择？",
    "created_at": "2026-07-21T08:30:00+08:00"
  },
  "run": {
    "id": "run-id",
    "status": "queued",
    "conversation_id": "conversation-id"
  }
}
```

同一用户、同一会话、同一 `Idempotency-Key` 必须返回同一个运行，不得重复扣费或重复执行。

### 6.4 查询和取消运行


状态：

```text

waiting_user
completed
failed
cancelled
```

运行响应：

```json

  "conversation_id": "conversation-id",
```

## 7. SSE 事件接口

### 7.1 连接

```http
GET /api/v1/agent/runs/{run_id}/events
Authorization: Bearer <access_token>
Accept: text/event-stream
Last-Event-ID: <event-id>
```

SSE 不使用当前 Axios 请求封装，前端使用 `fetch` 流读取。

### 7.2 事件格式

```text
id: 1710000000-42
event: tool_completed
data: {"event_id":"1710000000-42","sequence":42,"run_id":"run-id","data":{}}

```

统一事件 JSON：

```json
{
  "event_id": "1710000000-42",
  "sequence": 42,
  "event": "tool_completed",
  "run_id": "run-id",
  "conversation_id": "conversation-id",
  "data": {},
  "created_at": "2026-07-21T08:30:05+08:00"
}
```

当前后端已实现的事件类型：

```text
run_started
plan_created
tool_started
tool_progress
tool_completed
clarification_required
message_completed
run_completed
run_failed
run_cancelled
```

当前结构化 LLM 调用不提供 Token 流，因此前端不得伪造 `message_delta`。后续只有在 LLM 客户端实现真实流式输出后才增加该事件。

### 7.3 结构化完成结果

当前 `message_completed.data`：

```json
{
  "message_id": "message-id",
  "result": {
    "summary": "根据你的专业和技能...",
    "directions": [],
    "skill_gaps": [],
    "next_actions": [],
    "evidence_summary": [],
    "follow_up_questions": [],
    "disclaimer": "内容由 AI 生成，仅供参考，请结合自身情况进行判断。"
  }
}
```

完整持久化消息、工具证据和 metadata 以会话详情 REST 响应为准。前端收到终态后必须重新加载会话详情，不以 SSE 事件代替历史消息。

## 10. 错误规范

JSON 接口错误：

```json
{
  "code": 422,
  "msg": "参数校验失败",
  "data": {
    "field_errors": {
      "content": ["消息不能为空"]
    },
    "request_id": "request-id"
  }
}
```

常见业务码：

```text
401  未登录或 Token 失效
403  无权访问该会话、运行或任务
404  资源不存在
409  运行冲突或重复提交
413  文件过大
422  参数或文件类型不合法
429  超出 Agent 频率或并发限制
503  市场数据、模型或事件服务暂不可用
```

工具部分失败不应让整个首页接口失败，使用 `warnings` 表示部分降级；Agent 运行失败则发送 `run_failed`，不能以成功消息返回错误字符串。

## 11. Mock 到 API 的切换

当前数据入口：

```text
frontend/src/data/homeMockData.js
frontend/src/data/agentMockData.js
frontend/src/stores/agent.js
frontend/src/api/agent.js
frontend/src/utils/sseClient.js
```

已实现数据源配置：

```env
VITE_HOME_DATA_SOURCE=mock
VITE_AGENT_DATA_SOURCE=mock
VITE_AGENT_ENABLED=true
```

模式语义：

```text
mock   完全使用本地会话和规划演示数据
hybrid 会话、消息、运行和 SSE 使用真实 API，规划 Dashboard 使用演示数据
api    会话、消息、运行和 SSE 使用真实 API；未实现接口的 Dashboard 仍明确标记为演示数据
```

后续接入时：

1. 保持组件接收的数据字段不变。
2. 将 mock getter 替换为 API service。
3. 保留 `is_mock`、`source`、`data_as_of` 和 `warnings` 的渲染。
4. 先使用 `hybrid` 模式验证现有 `/analysis/stats` 与新首页契约。
5. Agent API 稳定后再切换 `VITE_AGENT_DATA_SOURCE=api`。

## 13. 联调验收标准

- 首页不再依赖硬编码数组即可显示后端返回数据。
- 后端部分失败时首页仍能展示可用模块和 warning。
- Agent 会话、消息和运行 ID 全部可恢复。
- SSE 断线重连不会重复创建消息或 AgentRun。
- 用户 A 无法读取用户 B 的画像、会话、任务和运行。
- 方向、技能、任务、岗位数据字段可直接映射到当前 Vue 组件。
- 所有市场数据都能显示来源、样本量和统计时间。
- 所有 AI 内容显示免责声明。

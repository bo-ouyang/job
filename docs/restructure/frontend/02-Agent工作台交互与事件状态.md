# Agent 工作台交互与事件状态

## 1. 核心用户流程

```text
进入 /agent
-> 输入自然语言
-> 创建会话
-> 创建 AgentRun
-> 实时显示分析阶段
-> 展示工具查询摘要
-> 展示增量回答
-> 输出方向、证据、差距和行动
-> 保存会话
```

## 2. 中央消息区域

消息时间线需要区分：

1. 用户消息。
2. Agent 追问。
3. 计划阶段。
4. 工具执行状态。
5. 市场证据。
6. 最终分析。
7. 错误和降级。

工具状态只显示用户可理解的信息：

```text
正在理解你的目标
正在查询杭州相关岗位
已分析 426 个岗位样本
正在统计高频技能
正在生成行动建议
```

不展示模型内部推理过程。

## 3. 事件到 UI 的映射

| SSE 事件 | UI 行为 |
|---|---|
| `run_started` | 创建运行状态条，禁用重复发送 |
| `plan_created` | 显示分析步骤摘要 |
| `tool_started` | 新增工具执行卡，状态为进行中 |
| `tool_progress` | 更新工具卡的摘要和进度 |
| `tool_completed` | 显示样本量、来源和数据状态 |
| `clarification_required` | 显示可直接回复的追问卡 |
| `message_delta` | 增量追加 Assistant 消息 |
| `message_completed` | 定稿消息并渲染结构化结果 |
| `run_completed` | 结束运行，启用输入和后续操作 |
| `run_failed` | 显示安全错误和重试入口 |
| `run_cancelled` | 显示已取消，允许重新规划 |

## 4. 输入区

必须支持：

- 多行文本。
- Enter 发送。
- Shift + Enter 换行。
- 运行中停止。
- 运行失败重试。
- 快捷问题。
- 第二阶段上传简历。

运行期间不能连续提交同一消息。停止和重试必须使用当前 `run_id`，不能重复创建消息。

## 5. 右侧信息面板

### 职业画像

字段状态分为：

```text
已确认
Agent 推测
信息缺失
```

推测字段需要用户确认后才进入长期画像。

### 候选方向

方向卡展示：

```text
方向名称
机会等级
岗位样本量
薪资范围
用户优势
主要差距
推荐理由
```

不要生成没有依据的 `87.36%` 式精确匹配分数，优先使用高、中、低或区间。

### 行动计划

行动计划使用可勾选结构，而不是单段 Markdown：

```text
本周
□ 完成 SQL 窗口函数练习
□ 完成一个公开数据项目

本月
□ 完善简历
□ 投递 20 个目标岗位
```

## 6. 断线、刷新和错误

状态区分：

```text
submitting
connecting
streaming
reconnecting
recovering
completed
failed
cancelled
```

断线策略：

1. 保存最后事件 ID。
2. 指数退避重新连接 SSE。
3. 重连失败后查询运行状态。
4. 运行已终态则直接恢复结果。
5. 运行仍活跃则继续监听。
6. 任何情况下不重新提交用户消息。

## 7. 移动端交互

- 会话列表使用抽屉。
- 画像、证据和行动计划使用折叠面板。
- 输入框固定在可视区域底部。
- 使用 `100dvh` 适配移动浏览器。
- 用户阅读历史消息时不强制滚到底部。
- 新消息到达时显示“有新内容”按钮。
